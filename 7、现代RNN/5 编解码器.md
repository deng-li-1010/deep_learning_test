# 9.6 编码器-解码器架构 通俗完整讲解（仅PyTorch代码解析）
原文来源：动手学深度学习 https://zh.d2l.ai/chapter_recurrent-modern/encoder-decoder.html
## 一、整体架构通俗理解
### 1. 解决什么问题？
日常很多任务是**输入一段不定长文本，输出另一段不定长文本**（序列转序列）：
- 机器翻译：英文句子（变长输入）→ 法语句子（变长输出）
- 文本摘要：长文章 → 短摘要
- 对话生成：用户提问 → 机器人回复
- 语音转文字：语音波形序列 → 文字序列

普通CNN/单层RNN只能处理固定长度输入或输出，做不到**输入输出长度都可变**，于是诞生**编码器-解码器（Encoder-Decoder）** 双组件架构。

### 2. 两大模块分工（大白话）
1. **编码器 Encoder**
   接收任意长度输入序列，把整条序列“压缩提炼”成一份**固定维度的全局状态state**，相当于读完一整段话，记住全部信息存进一个固定大小的记忆包。
2. **解码器 Decoder**
   拿着编码器产出的固定记忆包，一步一步逐个生成输出单词/字符，最终产出任意长度的输出序列。

### 3. 完整流程（机器翻译举例）
输入英文：`They are watching .`（4个词，变长）
1. Encoder读完4个单词，输出一份固定形状编码状态；
2. Decoder拿到这份状态，循环逐词生成法语：`Ils` → `regordent` → `.`（3个词，长度和输入不一样）；
3. 每生成一个词，会把刚生成的词作为下一轮输入，持续生成直到结束符。

### 4. 整体数据流
输入序列 → Encoder → 编码输出enc_outputs → 转为解码器初始状态dec_state → Decoder逐token生成输出序列

## 二、Encoder 编码器（PyTorch代码逐行详解）
### 完整代码
```python
from torch import nn

#@save
class Encoder(nn.Module):
    """编码器-解码器架构的基本编码器接口"""
    def __init__(self, **kwargs):
        super(Encoder, self).__init__(**kwargs)

    def forward(self, X, *args):
        raise NotImplementedError
```

### 逐行拆解
1. `from torch import nn`
   导入PyTorch神经网络模块，所有网络层、`nn.Module`基类都在这里。

2. `#@save`
   d2l专属标记，代表这段代码会保存到工具库，后续章节可直接复用，无代码逻辑作用。

3. `class Encoder(nn.Module):`
- 定义`Encoder`类，继承`nn.Module`：PyTorch所有神经网络必须继承这个基类，自带参数管理、自动求导、cuda迁移、保存加载等功能。
- 这是**抽象基类接口**，不是能直接跑的模型，只是规定所有编码器必须实现的标准模板。

4. `"""编码器-解码器架构的基本编码器接口"""`
   文档字符串，注释类功能，调用`help(Encoder)`可以查看。

5. `def __init__(self, **kwargs):`
   构造函数，创建类实例时执行；
   `**kwargs`：接收任意多不定关键字参数，留给后续子类（RNN Encoder/Transformer Encoder）自定义使用，兼容各种编码器超参。

6. `super(Encoder, self).__init__(**kwargs)`
   调用父类`nn.Module`的构造函数，初始化网络基础功能，必须写，否则网络无法正常工作。

7. `def forward(self, X, *args):`
- `forward`：PyTorch核心前向传播函数，模型实例`model(X)`时会自动调用这个方法，定义数据流经网络的计算逻辑。
- 参数`X`：**输入序列张量**，形状一般为`[批量大小batch, 序列长度seq_len, 词嵌入维度embed_dim]`，就是待编码的句子/文本。
- `*args`：可变位置参数，预留扩展，比如输入有效长度、掩码等附加信息（如padding掩码）。

8. `raise NotImplementedError`
   抛出未实现异常：因为这只是**标准接口模板**，没有写实际编码逻辑。
   后续我们用RNN、Transformer实现编码器时，会新建子类重写`forward`；如果直接实例化`Encoder`调用前向传播，会报错，提醒开发者必须自定义实现。

### Encoder接口规范总结
所有编码器子类必须重写`forward(X, *args)`，输入变长序列`X`，输出编码结果`enc_outputs`（包含全局状态/每一步隐藏层）。

## 三、Decoder 解码器（PyTorch代码逐行详解）
### 完整代码
```python
#@save
class Decoder(nn.Module):
    """编码器-解码器架构的基本解码器接口"""
    def __init__(self, **kwargs):
        super(Decoder, self).__init__(**kwargs)

    def init_state(self, enc_outputs, *args):
        raise NotImplementedError

    def forward(self, X, state):
        raise NotImplementedError
```

### 逐行拆解
1. `class Decoder(nn.Module):`
   解码器抽象基类，规定所有解码器必须实现两个核心函数：`init_state`、`forward`。

2. `def __init__(self, **kwargs):`
   同上，父类初始化，预留自定义超参。

3. `def init_state(self, enc_outputs, *args):`
   **独有核心方法**，编码器没有这个函数，作用：
   把编码器输出`enc_outputs`转换成解码器能用的初始隐藏状态`dec_state`。
- 参数`enc_outputs`：Encoder前向传播返回的全部输出（包含各时间步隐藏向量、全局记忆）；
- `*args`：扩展参数，常见传入输入序列有效长度，用来屏蔽padding无效字符；
- 返回值：解码器初始状态state（RNN就是隐藏层h/c，Transformer是记忆缓存）。

举个例子：RNN编码器会输出所有时间步隐藏向量+最后一步全局隐藏向量，`init_state`会提取最后一步全局向量，包装成解码器RNN的初始隐藏层。

4. `raise NotImplementedError`
   接口约束，子类必须重写，否则调用报错。

5. `def forward(self, X, state):`
   解码器前向传播逻辑：逐token生成文本。
- 参数`X`：解码器当前时间步输入，一般是上一步生成的单词token（训练时是目标序列已知前半段）；
- 参数`state`：当前时刻解码器隐藏状态，会随每一步生成更新；
- 返回：当前时间步预测输出（每个词表token的概率） + 更新后的新state（给下一轮使用）。

### Decoder接口规范总结
所有解码器必须实现两个函数：
1. `init_state(enc_outputs)`：把编码器输出转为解码器初始状态；
2. `forward(X, state)`：根据当前输入+历史状态，预测下一个词，并更新状态。

## 四、EncoderDecoder 合并整体模型（PyTorch逐行详解）
把编码器、解码器组装成完整可训练的序列转换大模型。
### 完整代码
```python
#@save
class EncoderDecoder(nn.Module):
    """编码器-解码器架构的基类"""
    def __init__(self, encoder, decoder, **kwargs):
        super(EncoderDecoder, self).__init__(**kwargs)
        self.encoder = encoder
        self.decoder = decoder

    def forward(self, enc_X, dec_X, *args):
        enc_outputs = self.encoder(enc_X, *args)
        dec_state = self.decoder.init_state(enc_outputs, *args)
        return self.decoder(dec_X, dec_state)
```

### 逐行拆解
1. `class EncoderDecoder(nn.Module):`
   完整序列转换模型基类，绑定一个编码器+一个解码器。

2. `def __init__(self, encoder, decoder, **kwargs):`
   构造函数入参：
- `encoder`：已经实例化好的编码器对象（继承上面`Encoder`基类）；
- `decoder`：已经实例化好的解码器对象（继承上面`Decoder`基类）；
- `**kwargs`：预留扩展参数。

3. `super(EncoderDecoder, self).__init__(**kwargs)`
   初始化父类网络模块。

4. `self.encoder = encoder`
   将传入的编码器保存为模型成员变量，网络会自动登记它的所有参数，训练时同步更新。

5. `self.decoder = decoder`
   同理保存解码器，参数纳入整体模型管理。

6. `def forward(self, enc_X, dec_X, *args):`
   完整模型前向传播流程，一次性走完编码+解码，训练时直接输入即可。
   参数说明：
- `enc_X`：编码器输入，源序列（机器翻译里的英文句子）；
- `dec_X`：解码器输入，目标序列（训练时的法语句子，teacher forcing教师强制输入）；
- `*args`：附加参数，如源序列有效长度。

7. `enc_outputs = self.encoder(enc_X, *args)`
   执行编码：把源序列`enc_X`送入编码器，得到全部编码输出`enc_outputs`。
   等价调用`encoder.forward(enc_X, *args)`。

8. `dec_state = self.decoder.init_state(enc_outputs, *args)`
   调用解码器的`init_state`方法，将编码器输出转换成解码器初始隐藏状态。

9. `return self.decoder(dec_X, dec_state)`
   执行解码：把目标输入`dec_X`和初始状态送入解码器，返回解码器每一步预测的词概率，作为整个模型的输出，用于计算损失、反向传播更新参数。

### 完整前向传播链路汇总
`enc_X`(源序列) → encoder → enc_outputs → decoder.init_state → dec_state
`dec_X`(目标序列) + dec_state → decoder → 预测输出

## 五、核心知识点通俗总结
### 1. 三大类分工
1. `Encoder`：只负责压缩输入序列，输出编码信息，无状态初始化函数；
2. `Decoder`：负责读取编码信息、逐一生成输出，独有`init_state`转换编码为初始记忆；
3. `EncoderDecoder`：组装两者，封装完整seq2seq前向流程，对外提供统一调用入口。

### 2. 核心优势
完美适配**输入、输出长度完全不相等**的序列任务，这是单一网络做不到的。

### 3. 可使用的场景（练习第二题答案）
除机器翻译外：
1. 文本摘要：长文本输入，短摘要输出；
2. 对话系统：用户问句输入，机器人回复输出；
3. 图像描述（Image Caption）：CNN充当编码器编码图片，文本解码器生成描述；
4. 语音识别：声学特征序列编码，文字序列解码；
5. 代码生成：自然语言需求输入，代码文本输出。

### 4. 练习第一题答案：编码器和解码器必须是同一种网络吗？
**不需要**。
- 经典组合1：RNN Encoder + RNN Decoder（基础seq2seq）；
- 经典组合2：CNN图像Encoder + Transformer Decoder（看图说话）；
- 经典组合3：Transformer Encoder + Transformer Decoder（大模型翻译）；
  编码器和解码器网络结构可以完全独立，只需要遵守统一接口规范（继承对应基类、实现规定函数）即可拼接。

## 六、整体逻辑一句话概括
编码器把变长输入打包成固定记忆，解码器拿着这份记忆，一步一步生成任意长度的输出；三层PyTorch基类只是统一标准接口，方便后续RNN、Transformer等不同模型复用这套架构逻辑。
