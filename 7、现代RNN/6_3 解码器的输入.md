# 核心结论先放前面
**训练模式 和 推理（预测）模式，解码器输入完全不一样！**
模型权重、网络结构不变，但**每一步送入解码器的 token 来源不同**，这也是 Seq2Seq 著名问题：**暴露偏差（Exposure Bias）**。

下面结合 d2l seq2seq 代码、张量实例分开对比。

> 前置约定
> 源句子：`I love china`
> 目标真实译文序列（标签Y）：`<bos>, 我, 热爱, 中国, <eos>`
> 目标词：
> `<bos>` 起始符，`<eos>`结束符

## 一、训练阶段：Teacher Forcing 强制教学
### 解码器输入构造代码（d2l train_seq2seq核心片段）
```python
bos = torch.tensor([tgt_vocab['<bos>']] * Y.shape[0], device=device).reshape(-1, 1)
dec_input = torch.cat([bos, Y[:, :-1]], 1)
```
假设标签 `Y = [我,热爱,中国,<eos>]`
`Y[:, :-1]` 去掉最后一列`<eos>` → `[我,热爱,中国]`
拼接bos后：
**dec_input = [<bos>, 我, 热爱, 中国]**

### 训练时解码器时序输入（一次性送入整段序列）
时间步1输入：`<bos>`
时间步2输入：**真实标签【我】**
时间步3输入：**真实标签【热爱】**
时间步4输入：**真实标签【中国】**

✅ 特点：
1. **不管上一步模型预测输出是什么，下一步强行喂【ground-truth真实单词】**
2. 训练时一次性把整条dec_input送入解码器并行计算所有时间步损失（并行加速）
3. 模型不需要依赖自身预测结果，梯度稳定、收敛更快

🎯 训练目标：使用 `dec_input` 去预测标签 `Y = [我,热爱,中国,<eos>]`

## 二、推理阶段（predict_seq2seq 自回归生成）
推理**没有真实标签可以用**！只能依赖模型自己生成内容。
流程是**循环逐时间步跑，不能一次性输入整条序列**：
1. **第1轮输入固定只有 `<bos>`**
   解码器输出第一个词，假设预测出：**我**
2. **第2轮输入 = 上一轮模型预测词【我】**
   解码器基于`<bos>`、我，预测下一词：**热爱**
3. **第3轮输入 = 上一轮模型预测词【热爱】**
   预测：**中国**
4. **第4轮输入 =【中国】**
   预测：`<eos>` → 遇到结束符停止生成

### 关键对比表格
|项目|训练（Teacher Forcing）|推理（自回归预测）|
| ---- | ---- | ---- |
|单步输入来源|**真实标签ground truth**|**模型上一步自己的预测结果**|
|输入序列|一次性完整输入：`<bos>,我,热爱,中国`|逐轮迭代，每次只输入**单个token**|
|并行性|所有时间步同时计算，可以矩阵并行|串行循环，一步算完才能走下一步，无法并行|
|是否依赖模型历史输出|不依赖|高度依赖，如果前面预测错，错误会不断累积|

## 三、举一个直观反例看差距
假设真实目标序列：`<bos>,A,B,C,<eos>`

### 训练时输入：`[<bos>, A, B, C]`
就算模型第1步错误预测成Z，**第二步依然喂真实A**，错误不会传递。

### 推理时
- t1：输入`<bos>` → 预测Z（出错）
- t2：**输入只能是上一步输出Z**，而不是真实A
  模型从来没在训练时见过 `Z` 作为输入，极易持续输出离谱内容 → **错误累积**

## 四、延伸知识点：暴露偏差 Exposure Bias（Seq2Seq经典痛点）
根本原因：
**训练时解码器看到的数据分布 ≠ 推理时解码器看到的数据分布**
- 训练输入：干净、正确的人类标准句子
- 推理输入：模型自己生成的、可能有错的句子
  模型没学习过“如何基于错误输入修正”，长文本生成容易越来越离谱。

后续解决方案（了解即可）：
1. 计划采样（Scheduled Sampling）：训练时有概率使用模型预测值替代真值，逐步模拟推理分布；
2. 对抗训练；
3. 现在大模型普遍使用的因果LM思路+更大数据缓解该问题。

## 五、补充和代码相关重要细节
1. **编码器在训练/推理行为完全一致**
   编码器永远完整读取整条源句子，不存在输入差异；差异**只存在解码器**。

2. 网络权重结构完全不变
   Encoder、Decoder网络、参数一套，不需要搭建两套模型；
   只是**前向传播时喂进去的数据不一样、运行逻辑（并行/循环）不同**。

3. 回到d2l代码对应现象
- train_seq2seq：dec_input一次性构造完整序列，一次forward跑完所有解码步
- predict_seq2seq：while循环，每次forward只传入单个token，不断刷新state

## 六、极简总结方便记忆
训练：有参考答案，每一步强制给正确单词；
推理：没有参考答案，只能自己用上一步生成的词喂给下一步。
