# 问题1：解码器如何使用编码器输出？完整流程+具象例子
先先理清两个关键点（先分清两个概念，很多人混淆）
> 编码器有两类输出：
> 1. `output`：**编码器每一步全部隐状态** $h_1,h_2,...,h_T$（本章基础seq2seq**没用到**，注意力章节才用）
> 2. `state`：**编码器最后时间步的多层隐状态** $h_T$ → **本章唯一传给解码器的数据**

原始Seq2Seq规则：
✅ 只用 `enc_state = enc_outputs[1]`（最后时刻隐状态）
❌ **不使用 enc_output（全部时刻隐状态）**

---
## 一、回顾代码里传递链路
```python
# 1.编码器前向
enc_output, enc_state = encoder(X)

# 2.解码器初始化隐状态：把编码器最终state拿过来
dec_state = decoder.init_state((enc_output, enc_state))

# init_state源码
def init_state(self, enc_outputs, *args):
    return enc_outputs[1] # 取出 enc_state

# 3.解码器forward接收 state，作为GRU初始隐藏状态
output, dec_state = decoder(dec_input, dec_state)
```

### 解码器内部两处使用编码器信息：
1. **用 enc_state 初始化解码器GRU的隐藏状态**
   GRU第一个时间步没有上一步隐状态，直接使用编码器最终隐状态作为起点；
2. **取出enc_state最后一层，作为全局上下文向量context**
   解码器**每一个时间步**，都把这个固定上下文向量和当前输入词嵌入拼接，送入GRU。

> 一句话总结：
> 编码器读完整个源句子，把整段语义打包进**最后一步隐状态**；
> 解码器拿着这个向量做两件事：①初始化自身GRU；②每个解码时刻拼接进输入。

# 二、搭建一套可复现的实验例子（带张量shape逐步骤推演）
## 超参设定（固定下来全程不变）
```
batch_size = 2        # 一批2条句子
源句子最大长度 T = 3 （encoder时间步）
目标句子最大长度 T' = 4（decoder时间步）
embed_size = 8        # 词嵌入维度
num_hiddens = 16      # GRU隐状态维度
num_layers = 2        # GRU2层
src_vocab=10, tgt_vocab=10
```

## 输入源数据（编码器输入X）
`X.shape = [batch, T] = [2, 3]`
假设
$$
X=
\begin{bmatrix}
1 & 2 & 3 \\
4 & 5 & 6
\end{bmatrix}
$$
含义：
样本1：词1，词2，词3
样本2：词4，词5，词6

## Step1：编码器向前传播
1. 词嵌入：`[2,3,8]`
2. permute → `[3, 2, 8]`（时间步放第一维）
3. GRU运算得到：
```
enc_output.shape = [3, 2, 16]   # 3个时间步全部隐状态（弃用）
enc_state.shape  = [2, 2, 16]  # (层数=2, batch=2, hidden=16)
```
👉 enc_state 存储：**读完源句子第3个词之后的隐状态**，包含整条源句语义。

> enc_state：
> 维度 `[num_layers, batch_size, num_hiddens]`
> enc_state[0]：第一层GRU最后时刻隐状态
> enc_state[1]：第二层GRU最后时刻隐状态

## Step2：解码器init_state加载编码器state
```python
dec_state = decoder.init_state((enc_output, enc_state))
# dec_state = enc_state，shape依然 [2, 2, 16]
```
✅ 这就是解码器GRU的**初始隐藏状态**
普通GRU如果不提供初始state，默认用全0向量；
Seq2Seq不使用零向量，直接灌入编码器总结出的句子信息。

## Step3 进入解码器forward（最关键：context构造）
假设当前解码器输入 `dec_input`（训练时强制教学输入）
`dec_input.shape = [2, 4]` 两条目标序列

### 步骤3.1 词嵌入+转维度
```python
X = self.embedding(dec_input).permute(1,0,2)
# X.shape = [4, 2, 8]  (tgt_time_step=4, batch=2, embed=8)
```

### 步骤3.2 从编码器传来的state构造全局上下文context
```python
context = state[-1].repeat(X.shape[0], 1, 1)
```
拆解：
1. `state[-1]` → 取**最后一层GRU隐状态**
   shape `[batch, num_hiddens] = [2,16]`
   ✅ state[-1] = enc_state[-1]，本质还是编码器第二层最终隐状态！
2. `repeat(4,1,1)` 在时间维度复制4份
   context.shape → `[4, 2, 16]`

> 核心特点：**所有解码时间步共用同一个context向量！不会随解码步骤变化！**
> 不管解码器生成第1个词、第2个词、第3个词……用的都是同一个由源句子总结出来的向量。

### 步骤3.3 词嵌入向量 拼接 context
```python
X_and_context = torch.cat((X, context), dim=2)
# X: [4,2,8]
# context: [4,2,16]
# cat后 → [4, 2, 8+16=24]
```
👉 这就是为什么解码器GRU输入维度设置为 `embed_size + num_hiddens`

### 步骤3.4 GRU执行运算
```python
output, new_dec_state = self.rnn(X_and_context, state)
```
- 输入1：拼接后的序列 `X_and_context`
- 输入2：初始隐藏状态 `state`（来自编码器enc_state）
  GRU逐时间步运算，不断更新内部隐状态。

### Step4 GRU输出映射单词
```python
output = self.dense(output).permute(1,0,2)
# [4,2,16] →线性层→ [4,2,10] →置换维度→[2,4,10]
```

# 三、用人话+句子实例完整模拟一个翻译场景
任务：源语言英文 → 目标中文
源句子（输入encoder）：`["I", "love", "china"]`（长度3）

1. Encoder依次读 I → love → china
   每读一个单词更新内部隐状态；读完china后，生成最终隐状态 enc_state
> enc_state ≈ “I love china” 整句话语义压缩向量

2. 把 enc_state 送给解码器：
    - 充当解码器GRU起点隐状态
    - 抽出最后一层作为固定context向量

3. 解码器开始逐词生成译文：
- 第1步输入`<bos>`
  向量 = `<bos>`嵌入 **拼接** context（I love china信息）→ GRU预测第一个词：**我**
- 第2步输入上一步预测词`我`
  向量 = `我`嵌入 **拼接同一个context** → GRU预测：**热爱**
- 第3步输入`热爱`
  向量 = `热爱`嵌入 **拼接同一个context** → GRU预测：**中国**
- 第4步预测`<eos>`，停止生成

❗重点缺陷直观体现：
不管生成哪个中文词，使用**完全相同的全局context**，没有区分重点。
比如生成“我”的时候无法重点关注原文“I”，生成“中国”无法重点关注“china”。
这就是后续注意力机制要解决的痛点：不再共用单一向量，每一步动态挑选encoder各个时刻隐状态。

# 四、容易踩坑的几个疑问总结
## Q1：编码器的 enc_output（所有时刻隐状态）本章没用吗？
对！基础Seq2Seq只使用 enc_state。enc_output全部丢弃；9.8注意力机制才会用上enc_output。

## Q2：`state[-1]`为什么取最后一层？
GRU多层堆叠：下层输出作为上层输入。最后一层隐状态融合最深层语义，表征能力最强，所以拿它当做全局上下文。

## Q3：context为什么要repeat？
解码器有多个时间步，张量维度要求时间维度对齐；repeat相当于把同一个原文摘要复制多份，供给每一步解码使用。

## Q4：训练 vs 预测阶段，编码器输出使用方式有没有区别？
**使用方式完全一致！**
唯一区别：解码器输入来源不同
- 训练：输入是真实标签（teacher forcing）
- 预测：输入是上一步自身预测结果
  但编码器→解码器之间的数据传递逻辑一模一样。
